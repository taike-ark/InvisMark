# 架构与算法（参考实现）

> 对应代码：[`invismark/core/`](../invismark/core/) ｜ 实测脚本：[`scripts/bench_matrix.py`](../scripts/bench_matrix.py)
> 产品级需求见 [项目说明书](wmforge-隐形水印项目说明书.md)；本文只讲**这一版参考实现怎么做的、为什么、边界在哪**。

---

## 1. 设计约束

| 约束 | 原因 | 结果 |
|---|---|---|
| 零第三方依赖 | 私有化/内网机器装不上包，少一个依赖少一类故障 | 运行时只依赖 numpy；PNG/RS/HTTP/SQLite/GUI 全用标准库 |
| 24 字节载荷 | 与说明书对齐：只放追溯码，不放明文 PII | RS(64,24) → 512 bit，抗 20 字节错误 |
| 单图 ≤ 2.5 s（2400 px） | 说明书 §1.4 的 M0 判据 | 实测 1.8–1.9 s（单核，纯 numpy） |
| fail-open | 批量检测不能因一张图崩掉 | 提取失败返回 `found=False`，不抛异常 |

## 2. 追溯码字节布局（24 B）

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | version | u8 | 格式版本，当前 `0x01` |
| 1–4 | resource_code | u32 | base36 资源编码（最多 6 位，`0-9A-Z`） |
| 5–6 | user_index | u16 | 用户索引；真实用户 ID 在服务端映射，水印内无明文 |
| 7–10 | embedded_minute | u32 | UTC 分钟数（自 2020-01-01 起，约可表示 8000 年） |
| 11–14 | serial | u32 | 序号，离线号段/批量任务用 |
| 15–18 | crc32 | u32 | 前 15 字节的 CRC32 |
| 19–23 | reserved | 5 B | 必须为 0 |

**为什么加 CRC + 保留位**：RS 解码最多纠 20 字节错误，但"纠错成功"不等于"是我发的码"。
CRC 与保留位构成第二道门限，把随机比特流误判成有效追溯码的概率压到 ~2⁻⁴⁰ 量级。
这也是说明书里"双门限"的落地方式。

## 3. 嵌入链路

```
RGB ──► YCbCr（只改 Y，色度原样保留）
    ──► 缩放到基准长边（默认 2400，边长对齐 16 的倍数）
    ──► 两级 Haar DWT → LL2（1/4 分辨率，等效 16 px 块）
    ──► 4×4 分块 DCT → 取 C(1,1) 与块内 AC 能量 E=Σ C(i,j)², (i,j)≠(0,0)
    ──► 比特置乱（seed）→ 每比特 K 块扩频（±1 平衡符号）
    ──► 注入：C(1,1) += sign · max(α·√E, floor·2.5^(L-1))，上限 MAX_AMPLITUDE·2^(L-1)
    ──► 逆 DCT / 逆 DWT → 基准成图
    ──► 差异回注原始分辨率（只把"改动量"缩放回去，避免整图重采样掉画质）
    ──► 与原始色度合成 → PNG（无损）
```

### 3.1 为什么是 `C(1,1)/‖AC‖` 这个比值

自然图里 `C(1,1)`（4×4 DCT 的中频）幅度随内容变化，直接量化绝对值会被"亮度/对比度/缩放"
整体放大缩小打乱。把注入幅度定义为 **`α·√E`（正比于块内纹理能量）**，等价于在
"归一化系数空间"改动固定量：

- 图像整体增益 `g` → `C` 与 `√E` 同乘 `g` → 信噪关系不变（画质与检出都稳）；
- 平坦块 `√E≈0` → 注入量趋近 0（不会在纯色区域画出可见纹理），所以另设 `floor`
  保证 8 bit 量化后仍有信号。

### 3.2 为什么每比特要 K 个块，且符号必须平衡

内容本身的中频系数是有偏的（自然图 `C(1,1)` 均值明显大于 0）。若扩频符号 `±1` 的数量
不平衡，相关器会把内容偏置当成水印能量——`K` 小时直接压过信号（实测未平衡版本在
K=29 时 BER≈5%，RS 全部失败）。因此：

1. 每个比特的 `K` 个块里正负各占一半（`K` 为奇数时丢弃一个块）；
2. 解码时先减**全局均值**，再减**每比特组均值**（文字/条纹图的偏置是空间局部的，全局去不干净）。

### 3.3 提取

```
可疑图 ──► 同样缩放到基准 ──► 同样的两级 DWT + 分块 DCT
      ──► 每块 c = C(1,1)（绝对系数）→ 去均值（全局 + 每组）
      ──► 与 seed 生成的 ±1 图案做相关 → 逐比特硬判决
      ──► 反置乱 → RS(64,24) 解码（≤20 字节错误）→ CRC32 + 保留位校验
      ──► {found, trace_id, confidence, corrected_bytes} / {found:false, reason}
```

判决用"绝对系数相关"而不是比值：注入是绝对幅度（`max(α√E, floor)`），匹配滤波器就应该
按绝对幅度对齐；同时整体增益为正时，相关符号不变，所以亮度/对比度变化不影响判决。

## 4. 参数与取舍

| 参数 | 默认 | 含义 | 调大 | 调小 |
|---|---|---|---|---|
| `alpha` | 0.60 | 纹理自适应注入幅度 | 更抗攻击，PSNR 下降 | 更隐形，鲁棒性下降 |
| `base_long_edge` | 2400 | 嵌入基准长边 | 更抗压缩，耗时↑ | 更快，抗压缩↓ |
| `MIN_AMPLITUDE` | 3.0 | 注入下限（L=1 时） | 平滑图更稳，画质略降 | 纯色图检不出 |
| `MAX_AMPLITUDE` | 24.0 | 注入上限 | 高强度块更强 | 防白/黑区截断 |
| `MIN_AC_ENERGY` | 9.0 | 视为"有内容"的能量门槛 | — | — |
| DWT 级数 `L` | 自动 | 1 或 2（块 8/16 px） | 更抗缩放 | 容量更大 |

自动级数规则：取能让"每比特 ≥ 8 块"的最大级数（`_auto_level`），保证 `k` 足够大。

实测标定（2400 px 基准）：`alpha=0.6` → PSNR 45–47 dB、SSIM ≥ 0.99、扩频 `K≈29–32`，
PNG 重存/噪声 σ=3/亮度+6%/3×3 模糊/缩放 0.5×–2× 全部检出，错误 seed 与无水印图全部拒绝。

## 5. 抗性与失效模式

| 攻击 | 结果 | 原因 |
|---|---|---|
| PNG/无损重存 | ✅ | 8 bit 量化误差远小于注入幅度 |
| 亮度/对比度/色彩 | ✅ | 归一化 + 绝对相关都对正增益免疫 |
| 高斯噪声 σ≤3 | ✅ | K 块扩频平均 + RS 纠错 |
| 缩放 0.5×/0.75×/2× | ✅ | 16 px 块落在"内容尺度"，归一化后网格近似对齐 |
| 3×3 模糊 | ✅ | 低频注入，模糊主要衰减高频 |
| **中心裁剪** | ❌ | 裁剪同时改变尺度与块网格相位，`index % 512` 的比特映射错位 |
| **小图（< 2400 px）** | ⚠️ | 先放大到基准，差异回注与再放大各损一次 SNR；且每比特块数 k 变小（800 px 时 k≈14），平滑图信噪比不足 |
| **纯色 + 细线文字** | ⚠️ | 中频能量集中在边缘，部分比特无票 |
| JPEG 强压缩 | ⚠️ 未实测 | 需要 Pillow；量化表会改变系数分布，属 M0 任务 |

**下一步（v0.2）**：在每幅图的 4 个相位上各铺一份水印 + 一个已知同步头，提取时用同步头
估计尺度/相位再解调——这是解决裁剪的标准做法，代价是容量降到 1/4。

## 6. 性能与内存

| 操作 | 2400×1800 | 备注 |
|---|---|---|
| 嵌入 | ~1.8 s | 纯 numpy，单核；4 vCPU 目标 ≤2.5 s ✅ |
| 提取 | ~0.35 s | 一次 DWT+DCT+相关 |
| 峰值内存 | 约 3–4× 像素数 | float32/float64 混合，2400 px 约 150–250 MB |

## 7. 存储与审计链

SQLite 单文件（`store.py`）：

```
tenants ──< users（user_index 唯一）
   └──< assets（sha256_orig / sha256_wm / psnr / ssim）
          └──< traces（trace_id 主键 → asset_id）
extracts（每次提取都留痕，含未命中）
audit_logs（action/actor/target/at + prev_hash/this_hash 链式）
```

- `user_index` 每租户自增，上限 65535，与真实用户 ID 唯一映射；
- 审计链 `this_hash = sha256(prev_hash || 规范化 JSON)`，`verify_chain()` 全链校验，
  证据包把这个校验脚本一起打包，做到"离开系统也能验"。

## 8. 与 wmforge / blind-watermark 的差异

| 维度 | wmforge / blind-watermark | 本项目 v0.1 |
|---|---|---|
| 变换 | 单级 DWT + 4×4 DCT + SVD 奇异值量化 | 两级 DWT + 4×4 DCT + 归一化 AC 扩频 |
| 载体 | SVD 最大奇异值（QIM） | `C(1,1)` 绝对幅度，α·√E 自适应 |
| 纠错 | RS(64,24) | RS(64,24)（独立实现，参数同构） |
| 位级兼容 | — | ❌ 不保证；交叉提取需统一实现 |
| 依赖 | numpy/opencv/PyWavelets | 仅 numpy |

说明书里的产品形态依赖"与存量图交叉提取"，那需要换成本项目的 `core/pipeline.py` 接口
后接 wmforge 实现；接口（`embed` / `extract` / `EmbedResult` / `ExtractResult`）已刻意做成可替换。
