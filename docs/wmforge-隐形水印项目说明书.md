## 1. 项目概述

### 1.1 背景

图片在社交平台、素材站、电商详情页、AI 生成内容等场景被二次转发、裁切、压缩后，**原图哈希与 EXIF 全部失效**，版权方无法证明"这张图是我的"。主流做法是加可见水印，但：

- 可见水印破坏画面，商用图客户不接受；
- 加水印后可被裁掉、PS 抹掉，事后无法举证；
- 图文类内容（设计稿、图纸、摄影、模板）泄露后无法定位**是哪个账号、哪次会话**泄露的。

### 1.2 目标

建设一套**云端 + 双端客户端**的图片盲水印（隐形水印）系统，实现：

1. **不可见**：嵌入后主客观画质无明显下降（PSNR ≥ 40 dB、SSIM ≥ 0.98，待实测）；
2. **可追溯**：从"一张被压缩/截图/裁切过的图"中恢复 24 字节追溯码 `trace_id`，反查到 **租户 / 用户 / 资源 / 分钟级时间**；
3. **可取证**：一键导出证据包（原图哈希、嵌入时间、第三方时间戳、提取报告），具备对外举证的可交付形态；
4. **双端可用**：手机端 30 秒完成"选图 → 嵌入 → 保存/分享"；电脑端支持单张与批量（≥ 200 张/批）离线处理。

### 1.3 范围

| 范围内（In Scope） | 范围外（Out of Scope） |
|---|---|
| 图片（JPEG / PNG / WebP / HEIC 输入）盲水印嵌入与提取 | 视频水印、音频水印、PDF 水印 |
| 24 字节追溯码生成、用户索引映射与反查 | 任意长文本水印（受载荷容量限制，见 §5.3） |
| 桌面端离线模式 + 移动端联网模式 | iOS 端完全离线本地算法（P2 再评估） |
| 证据包生成（哈希 / 时间戳 / PDF 报告） | 与法院、公证系统的系统级对接（人工交付） |
| 租户、密钥、审计、配额管理 | DRM 级版权保护（不防高级攻击，见 §12.4） |

### 1.4 成功判据（Go / No-Go）

M0 技术验证结束时，以下 4 项同时达标才进入 M1：

| 判据 | 阈值 | 测试方法 |
|---|---|---|
| 嵌入后画质 | PSNR ≥ 40 dB 且 SSIM ≥ 0.98（2400px 长边基准） | 500 张多题材样本集 |
| 平台压缩后检出率 | 微信/朋友圈级重压缩（长边 ≤ 1280、JPEG q60）≥ 90% | 见 §12.1 攻击矩阵 |
| 无水印图误报率 | ≤ 1×10⁻⁴（10 000 张无水印图测试） | 负样本库 |
| 单张耗时 | 4000×3000 图嵌入 ≤ 2.5 s（4 vCPU） | 基准压测 |

## 2. 术语表

| 术语 | 含义 |
|---|---|
| 盲水印 / 隐形水印 | 嵌入后肉眼不可见、提取时**不需要原图**即可恢复的水印 |
| trace_id | wmforge 生成的 24 字节紧凑追溯码，由「资源编码 + 用户索引 + 分钟级时间戳」组成 |
| 用户索引 user_index | 2 字节左右整数，通过 `build_user_index_map()` 与真实用户 ID 建立映射，**水印本身不含明文 PII** |
| seed / 密钥 | 决定嵌入位置与伪随机序列的种子，等价于提取权限；同一图必须用同一 seed 才能提取 |
| 基准图 | 统一缩放到长边 2400 的工作图，嵌入在该尺度上进行，再将差异回注原分辨率图 |
| prealign | 提取端的预对齐步骤（缩放/裁切/旋转的归一化），wmforge 管线内置 |
| fail-open | 提取不到时返回"未检出"而非抛错，保证大批量检测不中断 |
| BER | 误码率；RS(64,24) 可纠正 20 字节错误，约 31% 误码容忍 |
| 证据包 | 原图 SHA-256 + 嵌入记录 + 提取报告 + RFC 3161 时间戳 + 审计链摘要 |

### 3.3 关键交互约束（移动端）

1. **少一步输入**：打开即"最近项目 + 大按钮选图"，不设登录墙（设备码绑定租户，首次扫码授权）。
2. **结果即闭环**：嵌入完成页直接给「保存到相册 / 分享 / 复制溯源链接」三选一。
3. **压缩认知**：微信、抖音等平台二次压缩会显著降低检出率，App 内必须内置「分享渠道风险提示」，并给出"用原图发送"的引导，不做隐性承诺。
4. **隐私**：默认仅上传必要分辨率（长边 2400 基准 + 可选原图），上传前明示并可在设置内切换"仅传压缩基准图"。

### 3.4 视觉方向：液态玻璃

移动端采用**液态玻璃（Liquid Glass）**材质语言——参照 iOS 26 的光学行为（背景折射、边缘镜面高光、按压形变、色彩拾取），而非像素级复刻。四条硬约束：**玻璃只做浮层不做底色**、**一屏 ≤ 3 块玻璃**、**图片区域零玻璃**、**永远有降级路径**。

完整规范见配套文档 [移动端 UI 规范 · 液态玻璃](<wmforge-移动端UI规范-液态玻璃.md>)，可调参的视觉概念稿见 [design/mobile-glass-mockup.html](<../design/mobile-glass-mockup.html>)（浏览器直接打开）。

## 4. 技术栈选型

### 4.1 为什么选 wmforge

wmforge 是一个生产级盲水印完整管线（Python 包），核心特征：

- **算法**：DWT（小波）+ DCT + SVD 的变换域盲水印，在 4×4 DCT 块内改写 SVD 奇异值；
- **性能**：批量 SVD + einsum 4×4 DCT-II 的向量化内核，比逐块 Python 循环快 2–3×（官方描述）；
- **纠错**：Reed–Solomon RS(64,24)，可纠正最多 20 字节错误（约 31% 误码容忍），抗截图、压缩与轻度翻拍；
- **追溯码**：24 字节 `trace_id`，由资源编码 + 用户索引 + 分钟级时间戳组成，**水印内不存明文用户信息**；
- **完整管线**：白底压暗、2400 长边基准降采样嵌入、提取端 prealign、fail-open，单图 embed/extract 一条命令可跑；
- **依赖轻**：numpy / opencv-headless / Pillow / PyWavelets，纯 CPU、无 GPU、可嵌入任意 Python 服务；
- **兼容性**：与 blind-watermark 0.4.4 数值逐位兼容（同种子同结果），存量图可交叉提取。

来源：[wmforge（PyPI）](https://pypi.org/project/wmforge/)、[blind-watermark 项目](https://gitee.com/guofei9987/blind_watermark)。

### 4.2 与本场景的匹配度

| 需求 | wmforge 现状 | 结论 |
|---|---|---|
| 不可见 + 抗压缩 | 频域 + RS 强纠错，官方描述抗截图/压缩/轻度翻拍 | ✅ 满足 |
| 反查"谁泄露的" | 内置 24 B 追溯码 + 用户索引映射 | ✅ 直接可用 |
| 任意文字水印 | 载荷固定 24 B | ❌ 不支持，走 §5.3 元数据/可见水印补充 |
| 手机端本地运行 | 纯 Python + numpy/opencv，Android 可试 Chaquopy；iOS 困难 | ⚠️ 移动端默认走服务端 |
| 桌面端离线 | PyInstaller 可冻结 | ✅ 满足 |
| 抗高级去水印攻击 | 无对抗训练 | ⚠️ 见 §12.4，靠冗余嵌入 + 组合标识缓解 |

### 4.3 端技术栈

| 端 | 选型 | 理由 | 备选 |
|---|---|---|---|
| 移动端 | Flutter 3.x（Dart，**Impeller + FragmentProgram** 自绘液态玻璃）+ Android/iOS 原生插件（相机、相册、分享） | 一套代码双端，相册/相机/分享生态成熟，玻璃材质可控且能统一降级 | React Native（社区组件的 iOS 相册权限更碎，玻璃需桥接原生，双端难一致） |
| 桌面端 | **PySide6（Qt 6）+ Python 3.11 内核 + PyInstaller/Nuitka 打包** | 算法同语言、零跨语言 IPC 成本、MVP 最快（约 4 周） | Tauri 2 + React + Python sidecar（UI 更现代，+3 周） |
| 服务端 | FastAPI + Uvicorn + PostgreSQL 16 + Redis + MinIO/S3 + Celery/RQ | 异步 IO、OpenAPI 自带、与算法同栈 | Go 网关 + Python worker（规模上来后再拆） |
| Web 后台 | React 18 + Vite + Ant Design | 表格/审计/权限组件齐 | Vue 3 |
| 证据/时间戳 | 国密 SM3/SHA-256 哈希链 + RFC 3161 TSA + PDF 签名 | 对外举证的可验证形态 | 第三方存证平台 API |

> 桌面端推荐 PySide6 而非 Electron/Tauri 的理由：**内核就在 Python 里**，Electron 方案要多维护一层 Node↔Python 通信与两套打包链；代价是 UI 精致度略低，属可接受折中。若产品定位偏"C 端付费工具"、UI 是卖点，则改 Tauri + sidecar，算法层完全不动。

## 5. 算法与能力边界

### 5.1 嵌入链路

```
输入图 ──► 格式/EXIF 解析与方向纠正
        ──► 白底压暗、去 alpha
        ──► 长边缩放至 2400 基准图
        ──► 比特化 trace_id (24 B) ──► RS(64,24) 编码 ──► 伪随机置乱(seed)
        ──► DWT(1 级) → 4×4 DCT → 块内 SVD，按量化步长改写奇异值
        ──► 逆变换得到基准成图
        ──► 差异回注原分辨率图（保持原始尺寸与 ICC）
        ──► 输出：PNG(无损) / JPEG(q95+) / WebP，写嵌入记录
```

### 5.2 提取链路

```
可疑图 ──► 解码 + 方向纠正 ──► 缩放到基准尺度 ──► prealign（尺度/位移/小角度旋转归一化）
       ──► DWT/DCT/SVD 反向读奇异值 ──► 解置乱 ──► RS 解码（最多纠 20 B）
       ──► 得到 trace_id ──► 查证据库：资源编码 → 用户索引 → user_id / 嵌入时刻
       ──► 输出：{found: true, trace_id, user, embedded_at, 置信度, 证据链接}
       ──► 任一步失败：{found: false}（fail-open），不抛异常
```

### 5.3 能力边界（必须写进产品文案）

| 边界 | 说明 | 产品应对 |
|---|---|---|
| 载荷仅 24 B | 只能携带追溯码，不能当"文字水印"用 | 长文本/联系方式走 XMP/IPTC 元数据 + 可选可见角标 |
| 需同 seed 提取 | seed 丢 = 图不可解；seed 泄露 = 可伪造 | 租户级 seed 存 KMS，双人审批导出 |
| 不是 DRM | 不阻断复制，只做事后追溯 | 销售话术明确"取证"而非"防盗" |
| 平台强压缩有损 | 微信/抖音二次处理会降低检出率 | 检出率矩阵化呈现（§12.1），UI 提示 |
| 小图不适用 | 长边 < 800px 嵌入强度不足 | 上传前拦截并提示 |
| 不允许截屏级重编码的极端破坏 | 多次转码 + 裁剪 + 滤镜叠加 | 建议多张冗余 + 组合标识 |

## 6. 系统架构

### 6.1 服务端模块

| 模块 | 职责 | 关键点 |
|---|---|---|
| API Gateway | 鉴权、租户路由、限流、计量 | JWT + 设备码；按租户 QPS 配额 |
| 嵌入服务 | 同步小图 / 异步大批量 | ≤ 20 MB 走同步；批量走任务队列 |
| 提取服务 | 单图/批量检测 | fail-open，返回置信度与 BER 估计 |
| 追溯码服务 | 生成 trace_id、维护 user_index 映射 | 映射表不落对象存储 |
| 证据服务 | 哈希链、TSA 时间戳、PDF 报告 | 报告可离线校验（附验签工具） |
| 对象存储 | 原图/成图/报告，生命周期策略 | 成图默认 90 天，证据包长期 |
| 审计与配额 | 全量操作留痕，导出审计 CSV | 保留 ≥ 6 个月 |

### 6.2 桌面端架构（本地模式）

```
PySide6 UI
   ├── 批量队列管理（拖拽、文件夹扫描、进度、失败重试）
   ├── 本地 SQLite（映射缓存、任务记录）
   ├── 内核适配层 core/  ← 仅暴露 embed(路径, trace_ctx) / extract(路径)
   │      └── wmforge.pipeline
   └── 打包：PyInstaller --onedir，附带 opencv-headless + PyWavelets 动态库
```
> 打包体积估算：120–180 MB（含 numpy/opencv），需实测；不建议 `--onefile`（首启解压慢、杀软误报高）。

### 6.3 移动端架构

- Flutter：页面路由、相机/相册、任务队列（失败重试 + 断点续传）、本地缓存最近 50 条记录；
- 网络层：RestClient + 重试退避；大图先本地降采样到长边 2400 再上传（省流量、且与基准一致）；
- 结果：嵌入完成后从 CDN 拉取成图，写入相册（Android MediaStore / iOS PHPhotoLibrary）；
- 推送：批量任务完成通知（Android FCM / iOS APNs，国内渠道另接厂商推送）。

## 12. 鲁棒性与测试

### 12.1 攻击矩阵（M0 必须全量跑）

| 编号 | 攻击 | 参数 | 目标检出率（估算待实测） |
|---|---|---|---|
| A1 | JPEG 重压缩 | q95 / q75 / q60 / q30 | 100 / 98 / 92 / 75 (%) |
| A2 | 平台压缩 | 长边 1280 q60、长边 1080 q70 | ≥ 90 |
| A3 | 截图 | 1080p / 2K 截屏后保存 | ≥ 95 |
| A4 | 裁剪 | 保留 90% / 70% / 50% 面积（中心） | ≥ 98 / 80 / 50 |
| A5 | 缩放 | 0.5× / 0.75× / 2× | ≥ 95 |
| A6 | 轻度旋转 | ±3° 内（prealign 可纠） | ≥ 90 |
| A7 | 翻拍 | 手机拍屏，含反光/摩尔纹 | 需实测，估计 40–70 |
| A8 | 二次编辑 | 亮度/对比度 ±10%、轻度锐化 | ≥ 90 |
| A9 | 社交链路 | 微信原图发送 / 朋友圈 / 微博 | 逐个实测 |
| A10 | 无水印负样本 | 10 000 张 | 误报 ≤ 1e-4 |

### 12.2 测试集

- 正样本 1 000 张：摄影、插画、UI 稿、CAD 图纸、纯色/渐变、文字截图、低对比暗图、高噪点夜景；
- 负样本 10 000 张：公开数据集随机抽样（去重）；
- 分层报告：按题材/尺寸/亮度分桶给检出率，避免"平均达标、局部崩塌"。

### 12.3 验收方式

每个版本出《鲁棒性回归报告》（自动跑 A1–A10，产出 CSV + 折线图），低于基线的组合必须给出原因或修复计划。

### 12.4 已知对抗风险（必须向客户明示）

学术上已出现**黑盒水印去除/伪造**攻击：例如 NeurIPS 2025 的 [WmForger](https://github.com/facebookresearch/videoseal/tree/main/wmforger)（[论文](https://ar5iv.labs.arxiv.org/html/2510.20468)，仅需一张带水印图，用图像偏好模型做像素梯度优化即可剥离多种后处理水印）。我们的定位与对策：

| 风险 | 影响 | 对策 |
|---|---|---|
| 黑盒去水印工具 | 蓄意规避后无法检出 | ① 多频带/多副本冗余嵌入（P1 实验项）；② 与可见角标、XMP、C2PA 组合标识；③ 检出率低于阈值时在报告中标注"疑似处理"；④ 商业承诺限定为"非针对性攻击" |
| seed 泄露 | 可批量伪造/解码 | KMS + 双人审批 + 轮换；泄漏走版本化 seed，旧图仍可解 |
| 误报导致错误指控 | 法律风险 | 双门限（RS 解码成功 + 校验位/置信度），高置信才出报告 |

### 12.5 待实测确认的 3 个假设

1. **PSNR 基线**：wmforge 默认参数在 2400 基准下的实际 PSNR/SSIM（文档未给数值，需 M0 实测）；
2. **翻拍鲁棒性**：官方称"抗轻度翻拍"，需在 A7 上量化；
3. **ARM 端性能**：若要评估 Android 本地嵌入（Chaquopy），8 核手机单张耗时是否可接受。

## 13. 安全与合规

1. **个人信息最小化**：水印仅含 `user_index`（整数索引），映射表存服务端；截图/泄露图不直接暴露手机号、姓名。
2. **法规对齐**：
   - 《个人信息保护法》：映射表属个人信息，需告知+最小必要+可删除；
   - 《数据安全法》：取证数据分类分级，私有化客户数据不出内网；
   - 《电子签名法》：与司法鉴定/公证的对接按客户需求单独评估；
   - 面向 AI 生成内容的客户，需同时满足《人工智能生成合成内容标识办法》对**显式标识 + 隐式标识（元数据/水印）**的要求 —— 本系统的盲水印可承担隐式标识角色，须与元数据方案一起交付。
3. **证据链设计**：原图 SHA-256 + 成图 SHA-256 + 嵌入记录 + RFC 3161 时间戳 + 审计链，任一环可独立校验；PDF 内嵌验签指引，避免"只有我们系统的报告能证明我们系统的结论"。
4. **不允许的能力**：不提供"解码他人水印"的通用破解功能；提取接口只对本租户 seed 生效。
